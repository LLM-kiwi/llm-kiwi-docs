## Rate limits

Rate limits prevent abuse and keep the service fast for everyone.

| Limit | Details |
|-------|---------|
| Requests per minute | Varies by plan |
| Tokens per request | Standard context window |
| Concurrent requests | Limited |

If you exceed the rate limit, the API returns a `429` error. Wait a few seconds and retry.

**How to handle rate limits in code:**

```python
import time

def make_request_with_retry(client, messages, max_retries=3):
    for attempt in range(max_retries):
        try:
            response = client.chat.completions.create(
                model="auto",
                messages=messages,
            )
            return response
        except openai.RateLimitError:
            if attempt < max_retries - 1:
                time.sleep(2 ** attempt)  # exponential backoff
            else:
                raise
```

## Token usage

Every request consumes tokens. Tokens are chunks of text — roughly 1 token ≈ 0.75 words in English.

The API reports usage in every response:

```json
{
  "usage": {
    "prompt_tokens": 15,
    "completion_tokens": 50,
    "total_tokens": 65
  }
}
```

| Field | Meaning |
|-------|---------|
| `prompt_tokens` | Tokens in your input (messages + system prompt) |
| `completion_tokens` | Tokens in the AI's response |
| `total_tokens` | Total consumed |

**Tips to reduce token usage:**
- Shorter system prompts = fewer prompt tokens
- Set `max_tokens` to cap response length
- Remove old messages from multi-turn conversations

## Error codes related to limits

| Status | Meaning | What to do |
|--------|---------|------------|
| `429` | Rate limit exceeded | Wait and retry, or upgrade to Pro |
| `400` | Request too large | Reduce input length or `max_tokens` |

## Best practices

1. **Cache responses** — if you're asking the same question repeatedly, save the result
2. **Use `max_tokens`** — cap response length to what you actually need
3. **Implement backoff** — don't retry immediately after a `429`; wait and try again
4. **Monitor usage** — check the `usage` field in responses to track consumption
5. **Batch when possible** — combine multiple small requests into one if applicable
